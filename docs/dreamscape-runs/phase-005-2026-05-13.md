# Phase 5 — 2026-05-13 (concurrent multi-agent dreamscape)

Fifth real-world pass. Every prior phase tested **one** agent at a
time — in production, multiple agents share the same dreamscape
machinery (snapshots, SQLite shared memory, scheduler registry).
Phase 5 spins two agents up in parallel and stress-tests the
overlap.

## TL;DR

* **Shared memory**: 50 interleaved writes from two agents across
  the SQLite (WAL) backend → 100% success, p95 < 10ms, perfect
  per-agent isolation (25 rows each, no cross-writes).
* **Schedulers**: two `DreamScheduler`s running in parallel for 60s
  against real Haiku 4.5 → **15 dreams, 15/15 unique titles, 0
  errors**, independent imagination trait progression (0.08 vs 0.07).
* **Verdict**: dreamscape is multi-agent safe. No locks, no
  collisions, no cross-talk. Ready for daemon integration.

## Part 1 — shared memory under concurrent writes

Two coroutines each posting 25 entries to `SQLiteSharedMemory` with a
10 ms interleave delay. The backend already enables `journal_mode=WAL`
and `busy_timeout=5000`; we wanted to see if those defaults hold up
under realistic concurrent pressure.

| | agent_a | agent_b |
|---|---|---|
| Writes attempted | 25 | 25 |
| Writes succeeded | 25 | 25 |
| Max latency | 11.21 ms | 9.39 ms |
| p95 latency | 9.34 ms | 8.48 ms |

Total elapsed for all 50 writes: 0.77 s. Recent() returns 50 rows,
split exactly 25/25 by `agent_id` — no rows mis-attributed.

WAL mode is doing its job.

## Part 2 — two DreamSchedulers concurrent

Both schedulers started with the same accelerated config:
- `poll_seconds=3`
- `dormancy_after_seconds=5`
- `dreaming_after_dormant_seconds=2`
- `max_seeds_per_dream=2`
- `imagination_trait_increment=0.01` (production default — *not* the
  inflated 1.5 we used in Phase 3 to make the trait obviously rise)

Each agent's snapshot was pre-seeded with a 30-second-old
`last_activity_at` so the first tick saw DORMANT.

### Results

| | agent_a (alpha) | agent_b (bravo) |
|---|---|---|
| Ticks | 8 | 8 |
| Dreams fired | 8 | 7 |
| Skipped ineligible | 0 | 0 |
| Errors | 0 | 0 |
| Imagination after | 0.08 | 0.07 |
| Unique titles | 8/8 | 7/7 |

15 dreams total, 15/15 unique titles. Sample mix:

* agent_a: *threads under tension*, *the unfinished catalog*, *the
  web between stars*, *the breaking scaffold*, *the eight-legged
  typesetter*, *the boy who forgot his own composition*, *embedded
  astronomies*, *the Loom That Listens*
* agent_b: *patient weight*, *water that remembers its architects*,
  *the notation inside the wood*, *the perfectionist's thread*, *the
  architects who built for ghosts*, *signals in the cold*, *the
  Storyteller's Thread*

The eight-legged typesetter is showing up across phases — it's a
cross of the Smalltalk seed (Alan Kay, 1980s) with the
TeX/typography seed (Knuth, ten-year-bet). The seed library is
producing genuinely cross-domain phrases.

### Isolation check

`agent_a.imagination = 0.08`, `agent_b.imagination = 0.07`. Distinct.
agent_a fired one more dream than agent_b in the same window
(scheduling jitter — both ran for the same 60s but agent_a happened
to complete its 8th cycle just inside the window). Per-agent
snapshots updated independently with no writes from the other
scheduler.

## What this tells us about production cadence

At production defaults (`imagination_trait_increment=0.01`), agent_a
gained 0.08 trait in 60s — roughly **0.08/min**. The default
`min_imagination_trait=1.0` threshold needs **~12.5 hours of
continuous dreaming** before imagination injection unlocks. That's
deliberate: you have to "earn" the intervention by accumulating dream
hours. Phase 3's 1.5/dream was an acceleration knob for visibility,
not the production setting.
