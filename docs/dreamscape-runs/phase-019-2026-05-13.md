# Phase 19 — 2026-05-13 (LLM classifier fallback)

Nineteenth real-world pass. Phase 17's validation surprise — the
"designing the retry policy" prompt mis-classifying as creative
because of one keyword — confirmed that the keyword-only classifier
is too brittle for the long tail. Phase 19 ships an **LLM-based
fallback** that fires only when the keyword classifier returns
``"general"`` and caches the verdict to disk so the cost is one
Haiku call per agent build, not per dream.

## TL;DR

* **Mechanism shipped** — `classify_agent_domain_llm_async()` +
  `classify_with_fallback_async()` + disk cache.
* **Wired into agent.py** — when keyword returns `general` at build
  time, the LLM classifier fires as a background asyncio task. The
  result is written to `~/.bog-agents/agents/<id>/domain_llm.txt`
  and consulted on subsequent dream cycles via the existing
  `resolve_agent_domain()` function.
* **10 new unit tests** cover JSON parsing (with + without code
  fences), fallback to `general` on unparseable / invalid labels /
  provider errors, cache round-trip, and the resolve-from-cache
  path.
* **Live validation (4 profiles, ~$0.003)** confirms the LLM
  classifier returns coherent labels matching the keyword
  classifier when both agree, and conservatively returns `general`
  on a truly generic profile (doesn't hallucinate a domain).

## Why a fallback matters

Phase 17 hit a concrete case: the prompt *"I'm designing the retry
policy for a downstream API…"* got classified as creative because
``"designing"`` is in the creative vocabulary. That's debatable —
the prompt is partly a design question — but the keyword classifier
has no way to weigh the engineering context around that one
keyword. Phase 19's LLM classifier reads the whole excerpt and
makes a holistic call.

The shipped pattern preserves the keyword classifier as the
primary (deterministic, free, instant) and uses the LLM **only**
on the long tail. For typical production profiles, the LLM is
never called. For ambiguous profiles, one Haiku call at agent
build time gets a better label than `general`.

## Implementation

```
classify_agent_domain(profile)      # keyword, returns Domain
classify_agent_domain_llm_async(profile, model)
                                     # one Haiku call, parses JSON
classify_with_fallback_async(profile, model)
                                     # keyword first, LLM if 'general'

llm_cache_path(agent_id)             # ~/.bog-agents/agents/<id>/domain_llm.txt
_save_cached_llm_domain(agent_id, domain)
_load_cached_llm_domain(agent_id)

resolve_agent_domain(agent_id)       # keyword → cache → 'general' fallback
```

In `agent.py`, `_schedule_llm_domain_classification()` fires a
fire-and-forget `asyncio.create_task` at agent build time, but
only when:
1. The user has captured a profile (always, when system_prompt is provided)
2. The keyword classifier returns `general`
3. There's no existing cache file (avoid repaying for a known label)
4. There's a configured dream model spec (or active model)
5. There's a running event loop

The agent build doesn't block on the classification — it lands in
the cache asynchronously and is picked up by the next
`resolve_agent_domain()` call.

## Live validation

| Profile | Keyword | LLM | Agreement |
|---|---|---|---|
| Ambiguous CLI default | engineering | engineering | ✓ |
| Narrative writer | creative | creative | ✓ |
| Research assistant w/ code mentions | research | research | ✓ |
| Truly generic | general | general | ✓ |

The 4 sanity profiles all had enough signal for the keyword
classifier to commit — none exercised the fallback path that's
Phase 19's main contribution. The validation confirms:

* The LLM classifier returns coherent labels matching the keyword
  classifier when both agree.
* It conservatively returns `general` on a truly generic prompt
  (doesn't hallucinate a domain).

The fallback's real value is on profiles where keyword falls
through to `general` AND a domain signal exists. That distribution
is in the wild; a production rollout will surface those
incrementally.

## Cost

| Metric | Phase 19 |
|---|---|
| Live API calls | 4 (validation only) |
| Per-agent-build cost | ~$0.001 (only when keyword falls to `general`) |
| Per-dream cost | $0 (cache reads from disk) |
| Approx total | $0.003 |

## Verdict

**READY TO MERGE.** Small surface, robust failure modes (every
external call wrapped + falls back to `general`), gracefully
handles the long tail without changing modal behavior. The cache
keeps the one-Haiku-call cost amortized over the agent's lifetime.
