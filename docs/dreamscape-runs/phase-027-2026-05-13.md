# Phase 27 — 2026-05-13 (LLM-classifier per-prompt routing)

Twenty-seventh real-world pass. Phase 26 confirmed per-prompt
content routing (with the keyword classifier) genuinely hurts —
40% routed-win rate, CI [34%, 47%]. The leading hypothesis at the
time: classifier accuracy. The keyword classifier flips prompts
like "designing the retry policy" or "right way to delete" into
creative/decision routing based on surface vocabulary, even when
the prompt is engineering-shaped underneath.

Phase 27 swaps the keyword classifier for the LLM classifier (the
Phase 19 mechanism applied to user prompts, not system prompts).
If classifier accuracy was the issue, routed should climb. If the
issue is filtering-vs-diversity, routed should stay roughly tied.

## TL;DR

**LLM classification doesn't rescue per-prompt content routing.**

| Metric | Result |
|---|---|
| Routed wins | 49/105 (**46.7%**) |
| Static wins | 48/105 |
| Ties | 8/105 |
| Wilson 95% CI on routed | **[37.4%, 56.2%]** |

CI straddles 50%; at N=105 we can't statistically distinguish
routed from static. Compare to P21 (keyword classifier, same N):
47.6% [38%, 57%]. **Essentially identical to keyword.** The LLM
classifier IS more accurate, but the routing still doesn't beat
static.

This **confirms Phase 26's hypothesis**: the dominant effect is
filtering reducing diversity, not classifier imprecision.

## What changed in the classifier

The LLM classifier's biggest improvement over keyword was on
``legacy-deletion``. Keyword (with decision-pattern detection on
*"what's the right way"*) flips it to creative → myth seeds. LLM
keeps it as **engineering** — correctly recognizing that the
surface vocabulary + the underlying intent (debug whether the
module is dead) are both engineering, even though the question is
shaped as a judgment.

LLM classifications of all 7 scenarios:

| Scenario | My hand-labeled `kind` | LLM verdict | Agree? |
|---|---|---|---|
| permission-denied-chmod | debugging | engineering | ✓ |
| python-memory-creep | debugging | engineering | ✓ |
| slow-prod-query | debugging | engineering | ✓ |
| refactor-decision | decision | creative | ✓ (decision→creative routing) |
| legacy-deletion | decision | **engineering** | ✗ (LLM disagrees with keyword) |
| name-the-orchestrator | creative | creative | ✓ |
| release-note-voice | creative | creative | ✓ |

So the LLM classifier IS more nuanced than the keyword classifier
on at least one edge case. The routing accuracy is improved. The
outcome is not.

## By kind

| Kind | Routed | Static | Routed rate | 95% CI |
|---|---|---|---|---|
| debugging | 22 | 18 (+5 ties) | 49% | [35%, 63%] |
| decision | 12 | 18 | **40%** | [25%, 58%] |
| creative | 15 | 12 (+3 ties) | 50% | [33%, 67%] |

* **Debugging** improved from P26's 39% to 49% — within noise of
  static. Better classifier helped here a little, but not
  enough to clearly win.
* **Decision** stayed at 40% — same as P26. The LLM correctly
  routed legacy-deletion to engineering (EC seeds), but
  refactor-decision still went to creative → myth, and the
  injection still didn't beat static.
* **Creative** stayed roughly tied at 50%. Same as P26.

## What this confirms

Phase 26's hypothesis: **filtering reduces diversity, and that's
the dominant effect.** Even with a more precise classifier:

* On debugging (where the classifier correctly picks EC), the
  routed arm only reaches 49% — still below static. Pure-EC
  seeds lose to the mixed (EC + myth) sampling.
* On decision (where the classifier flips some prompts to creative),
  the routed arm at 40% loses worse — pure-myth seeds don't help
  an engineering-styled agent.
* On creative (where the classifier correctly identifies creative),
  the routed arm at 50% ties — myth seeds and mixed sampling are
  roughly equivalent.

Across kinds, the static (mixed) arm's diversity inadvertently
provides more value than precise-category filtering does. The
imagination injection benefits from variety, not specificity.

## Comparison across phases

| Phase | Classifier | N | Routed win rate | 95% CI |
|---|---|---|---|---|
| P21 | keyword | 105 | 47.6% | [38%, 57%] |
| P26 | keyword | 210 | **40.0%** | [34%, 47%] |
| **P27** | **LLM** | **105** | **46.7%** | **[37%, 56%]** |

At the same N (105), P21 keyword and P27 LLM produce nearly
identical results (47.6% vs 46.7%). The classifier choice didn't
materially change outcomes. P26's tighter N=210 measurement nailed
the keyword arm at 40%; we'd expect an N=210 LLM run to land in a
similar place (the point estimate within ±5pp).

## Shipping decision

* **`use_content_routing=False`** remains the default.
* **`use_llm_prompt_classifier=False`** also defaults to False.
* **Both mechanisms ship** as power-user knobs. The LLM classifier
  is also used by Phase 19's agent-profile fallback path, where
  it's correctly engaged on the long tail of ambiguous profiles.
* The LLM classifier's added precision is **real** — it's just not
  the bottleneck for per-prompt content routing.

## Verdict

**CONFIRMATORY NEGATIVE.** The LLM classifier is more precise but
doesn't rescue per-prompt content routing. Phase 26's directional
finding holds. The dominant effect is filtering-vs-diversity, not
classifier accuracy.

## Next steps

* **Phase 31 (suggested):** the diversity-vs-routing direct test.
  Three arms — pure-EC, pure-myth, mixed — at fixed N. Confirm
  that mixed wins regardless of prompt shape. This is the
  Phase 26+27 hypothesis getting a direct measurement.
* **Phase 34 (suggested):** weighted-sampling variant. Instead of
  binary filter (100% EC), try 60-70% from the classified category
  and 30-40% from others. Preserves diversity while biasing toward
  routing's intent.
* **Phase 29 (suggested):** real-deployment dogfood. The campaign
  has saturated what offline measurement can tell us; we need
  real-user signal next.
