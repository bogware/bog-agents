# Phase 13 — 2026-05-13 (routing verification)

Thirteenth real-world pass. **The smoke test for the context-aware
dreaming layer shipped in Phase 11+12's commit.** The new
`dreamscape/domain.py` module adds three coupled behaviors:

1. Classifier reads the captured agent profile and returns a domain
   (`engineering | creative | research | general`).
2. Dream engine picks seed categories per domain.
3. Imagination middleware picks injection wrapper style per domain.

Phase 13 verifies all three work end-to-end against real disk I/O +
a small live LLM check.

## TL;DR

* **Part 1 (mechanistic, no LLM cost):** 14 assertions pass —
  classification, profile round-trip, seed preferences, and
  injection style mapping all behave as documented.
* **Part 2 (live, $0.004):** 4 prompts (2 technical + 2 creative)
  routed through an engineering-classified agent. **Every call
  used the neutral wrapper. Zero dream-prefix leakage. All
  observation labels.**
* The routing layer is correct end-to-end.

Live check (4 prompts against engineering-classified agent):

* All 4 used the neutral wrapper.
* All 4 had `## Additional context` header.
* All 4 had `**Observation N**` labels.
* **Zero** had `## You appear to be stuck` header.
* **Zero** had `**Fragment N**` labels.
* **Zero** leaked `Tonight I dreamed of` titles into the system prompt.

The neutral wrapper's de-framing pipeline (header swap + label swap
+ `_strip_dream_prefix`) is air-tight in the wild, not just in the
unit test.

## Note on the trade-off

The two creative prompts (name-the-orchestrator and
feature-shape) routed through the engineering profile produced
direct, tool-naming responses — not the evocative reframes
Phase 11's creative-classified agents got. **This is intentional:
an engineering-classified agent should respond like an engineer
even on edge-case creative prompts.** The cost is that an agent
which legitimately spans both domains won't get the Phase 11
treatment-win lift on its creative work.

For agents that genuinely sit between domains (e.g. a dev-tool
designer), a future enhancement would be per-call routing — classify
the *prompt*, not just the agent. That's deferred; Phase 13 confirms
the agent-level routing works as designed.
