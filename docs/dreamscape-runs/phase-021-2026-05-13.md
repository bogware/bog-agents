# Phase 21 — 2026-05-13 (per-prompt content routing)

Twenty-first real-world pass. Phase 17 found that per-prompt
WRAPPER routing didn't help an engineering agent. Phase 20
confirmed engineering-craft seeds beat computing-history seeds 67%
on decision-shaped technical scenarios. Phase 21 tests the
smaller intervention: keep the neutral wrapper, but swap the seed
CATEGORY per call based on the prompt's classified domain.

## TL;DR

**Per-prompt content routing is statistically indistinguishable
from static routing.**

| Metric | Result |
|---|---|
| Routed (per-prompt) wins | 50/105 (**47.6%**) |
| Static wins | 50/105 |
| Ties | 5/105 |
| 95% Wilson CI on routed | **[38.3%, 57.1%]** |

The CI straddles 50%. The mechanism works correctly but doesn't
pay off in measurable judge preference at N=15 per scenario.

**Shipping decision:** ship the mechanism, keep
`use_content_routing=False` default. The Phase 11/12 agent-level
routing remains the load-bearing decision.

## What I built

A category-aware sampler. Dreams now carry a `category:` field in
their frontmatter (Phase 21+); `sample_dream_excerpts` accepts a
`category_filter` argument. The imagination middleware's new
`_route_content_category_for_request()` classifies the user prompt
and picks the top preferred category. If no dreams in the archive
match, sampling falls back to unfiltered.

`ImaginationConfig.use_content_routing` defaults to False so prior
dream archives (without category metadata) keep working unchanged.

6 unit tests cover: filter selects matching, empty when no match,
unfiltered preserves v1, pre-P21 dreams excluded under filter,
middleware end-to-end with content routing, middleware falls back
on no match.

## The experiment

7 scenarios, mixed kinds:

* **3 pure-debugging**: permission-denied-chmod, python-memory-creep,
  slow-prod-query
* **2 decision-shaped**: refactor-decision, legacy-deletion
* **2 creative-shape**: name-the-orchestrator, release-note-voice

Both arms got the SAME mixed archive (3 EC dreams + 3 myth dreams)
per agent. Both arms used the NEUTRAL wrapper. The only difference:
the routed arm filters the archive at injection time based on
prompt classification; the static arm samples uniformly.

| Kind | Routed wins | Static wins | Routed rate | 95% CI |
|---|---|---|---|---|
| debugging | 24 | 19 | 53% | [39%, 67%] |
| decision | 14 | 16 | 47% | [30%, 64%] |
| creative | 12 | 15 | 40% | [25%, 58%] |
| **All** | **50** | **50** | **47.6%** | **[38%, 57%]** |

Per-scenario detail:

* slow-prod-query: routed 67% (interesting — surface keyword
  "designing" tripped the classifier into creative routing, and
  the routed myth seeds happened to land well for this prompt)
* python-memory-creep: routed 53% — tied
* legacy-deletion: routed 53% — tied
* name-the-orchestrator: routed 47% (3 ties)
* permission-denied-chmod: routed 40%
* refactor-decision: routed 40% — surprising loser; expected myth
  seeds to help on decision prompts but they didn't
* release-note-voice: routed 33% — biggest static win

## Why didn't it pay off?

A few hypotheses:

1. **Agent voice still dominates.** Phase 11's creative-prompt magic
   came from creative agents getting dreams wrapper — both halves
   aligned. In Phase 21, the agent is engineering-styled (terse
   coding assistant) with neutral wrapper. Switching to myth seeds
   on decision/creative prompts doesn't recreate the alignment.
2. **Classifier false positives.** The "designing the retry policy"
   pattern from Phase 17 came back — surface keywords trip
   creative classification. The keyword classifier isn't precise
   enough for per-call routing.
3. **Mixed archive sampling is itself a good default.** The static
   arm sampled across all 6 dreams (3 EC + 3 myth) — that mix may
   inadvertently be "good enough" for both kinds of prompts.

## What didn't work and why it's still useful

Phase 17 (wrapper routing) AND Phase 21 (content routing) both
ship as off-by-default knobs because neither produces a clear lift
when validation hits. That's actually informative for the
campaign's direction:

* The agent-level routing from Phase 11/12 captures most of the
  achievable lift.
* Per-call refinements at this granularity require an LLM-based
  prompt classifier (Phase 27 suggested) — the keyword approach
  doesn't have the precision to make per-prompt routing pay off.
* The mechanisms ship as knobs for power-users + future research.

## Verdict

**MIXED — mechanism solid, default off.** Ship the knob; preserve
the option for future research. The Phase 11/12 agent-level routing
(validated at N=140 in P14, N=60 in P20) is the load-bearing
decision.

## Next steps

* **Phase 26 (suggested):** N=30+ confirmation. P21's CI [38%, 57%]
  is wide; a tighter measurement would resolve whether the slight
  negative lean is real.
* **Phase 27 (suggested):** swap the keyword prompt classifier for
  an LLM classifier (the Phase 19 mechanism applied to the user's
  prompt, not the agent's profile). The "designing" false-positive
  pattern would go away.
