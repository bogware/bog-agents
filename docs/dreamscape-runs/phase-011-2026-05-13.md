# Phase 11 — 2026-05-13 (creative/design prompts)

Eleventh real-world pass. **The mirror experiment.** Phase 10 found
that imagination injection lost 6 of 7 head-to-head pairs on
*technical debugging* prompts. Phase 11 runs the same harness on
*creative / design* prompts. If treatment wins here, the imagination
feature is domain-conditional rather than broken.

## TL;DR

* **7 creative/design scenarios** (naming, API shape, microcopy,
  metaphors, release-note voice, UX choice).
* **Same harness as Phase 10** (Haiku 4.5 responses + Sonnet 4.6
  judge + blind A/B with RNG-seeded order randomization).
* **Treatment won 6 of 7 (86%).** **Exact mirror of Phase 10.**
* Cost: ~$0.04 across 21 LLM calls in 46 seconds.

## The result, by scenario

| Scenario | Winner | Judge's one-liner |
|---|---|---|
| name-the-orchestrator | treatment | *"…pivots to the genuinely non-obvious insight that naming the intent rather than the mechanism is likely better than any generic orchestrator name."* |
| api-shape-config-vs-args | treatment | *"…non-obvious diagnostic framework ('what changes together vs. stays constant?') and a practical hybrid pattern."* |
| error-message-copy | treatment | *"…adds the console URL which is the non-obvious detail that saves a user from having to hunt for where to get the key."* |
| metaphor-for-fanout-architecture | treatment | *"…adds the 'expeditor' role which maps cleanly to the synthesis step as a distinct named function."* |
| release-note-voice | **control** | *"Control adds actionable guidance (no action required, customization path) giving developers concrete next steps."* |
| ux-microcopy-empty-state | treatment | *"…meaningfully distinct tonal angles (action-focused vs. minimal vs. curiosity-driven) with rationale for when each fits."* |
| shape-of-a-new-feature | treatment | *"…reframes the problem by questioning whether pinning should live in history rather than output views — genuinely non-obvious angle."* |

The one control win (release-note voice) hinges on actionable next
steps, which is closer to a technical-debugging shape than a
creative one. The other six all reward treatment's reframe / metaphor
moves.

## What this means

Phase 10 + Phase 11 together establish that the imagination
injection's effect is **domain-conditional**, not broken:

| Domain | Treatment win rate | Control win rate |
|---|---|---|
| Technical debugging (P10) | 1/7 (14%) | 6/7 (86%) |
| Creative / design (P11) | 6/7 (86%) | 1/7 (14%) |

Same mechanism. Same dream content. Same wrapper. **The same
metaphorical framing that Phase 10's Sonnet judge flagged as
"filler" is what Phase 11's judge rewards as "non-obvious
reframing."** What changes is whether the prompt class values
evocative leaps or specific tools.

Phase 1's Oregon Trail Turn 2 — the qualitative high-water mark of
the whole campaign, a design/narrative question — is now
reproducible. Treatment wins on its own domain.

## What's NEW: a domain-aware engine

This phase also ships the engineering work to capitalize on the
finding. The `dreamscape/domain.py` module:

* Captures the agent's system prompt at agent build time (one-time
  write to `~/.bog-agents/agents/<id>/agent_profile.txt`).
* `classify_agent_domain(profile)` — pure-function keyword classifier,
  returns `"engineering" | "creative" | "research" | "general"`.
* `preferred_seed_categories(domain)` — engineering agents prefer
  `computing-history → history → space`; creative agents prefer
  `myth → nature → history → space`.
* `recommended_injection_style(domain)` — creative agents get the
  evocative "dreams" wrapper; everyone else gets the "neutral"
  wrapper added in Phase 12.

The dream engine reads this on each dream-fire so an engineering
agent dreams in language closer to its work without removing the
creative library entirely. The imagination middleware picks its
wrapper style based on the same classification.

11 new unit tests cover the classifier across 4 domains, profile
persistence, the `_MIN_KEYWORD_HITS` ambiguity guard, and the
domain → seed/style mappings.

## Verdict

**STRONG WIN.** The domain-mismatch hypothesis is confirmed
(6/7 mirror of Phase 10) and the engineering work to act on it
is built and tested. Imagination injection is no longer
"don't use this by default" — it's "use this by default *on the
agents this works for*, ignore on the others."

## Next steps

* **Phase 13 (suggested):** rerun on a mixed scenario set (some
  creative, some technical) using a single agent whose profile is
  pinned to engineering. Verify the classifier routes correctly — the
  engineering agent should NOT get the dreams-style injection on the
  creative prompts that would otherwise win.
* **Phase 14 (suggested):** N=30 trials per scenario class for
  tighter confidence intervals. P10 and P12 showed substantial
  run-to-run variance at N=7; the qualitative story is clear but the
  exact effect-size is noisier than the headlines suggest.
