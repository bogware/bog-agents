# Phase 3 — 2026-05-13 (multi-cycle dream scheduler validation)

Third real-world dreamscape pass. **The big one — until now, `maybe_dream` was a callable nothing was calling.** Phase 3 wires it into an asyncio background timer (`DreamScheduler`) and validates a multi-cycle dormancy run live against the real Anthropic API.

## TL;DR

Built a 250-line `DreamScheduler` module, wired it into `LifecycleMiddleware`'s first async call via a lazy-start factory, ran it for **90 seconds with real Haiku 4.5 against an aggressive accelerated schedule** (5s dormancy + 2s dreaming + 3s poll). Results:

- **10 dreams fired in 90 seconds** (~6.7/min)
- **10/10 unique titles** — RNG seeding produced distinct dream seeds every cycle
- **0 errors** across 11 ticks
- **Imagination trait compounded 0 → 15.0** exactly as designed (1.5 × 10 = 15)
- **0 rate-limit hits** — every cycle had room to fire

**The dream scheduler sings.** Multi-cycle dormancy/dreaming/dormant transitions work cleanly under repeated load.

## What I built

```
bog_agents_cli/dreamscape/scheduler.py   # 250 lines, new
├── DreamScheduler           # asyncio task that polls maybe_dream
├── DreamSchedulerStats      # in-memory counters for observability
├── ensure_scheduler()       # singleton-per-agent_id constructor
├── get_scheduler()          # registry lookup
└── stop_all_schedulers()    # test teardown helper
```

Wired into `LifecycleMiddleware` via a new `dream_scheduler_factory` constructor argument. `agent.py` builds the factory closure (defers model construction so we don't pay LLM-provider load cost when scheduler is off) and passes it to the middleware. The middleware fires the factory on its **first async call** so we're guaranteed a running event loop.

5 unit tests pin the scheduler's behavior: start/stop idempotency, fires at least one dream, rate-limit window respected, emergency-disable env var skips, registry singleton.

## Live test details

90-second wall clock with:

| Knob | Value | Production default |
|---|---|---|
| Model | Haiku 4.5 | Haiku 4.5 |
| Poll interval | 3 s | 60 s |
| Dormancy window | 5 s | 1800 s |
| Dreaming window | 2 s | 600 s |

The accelerated config compresses what would be a 30-min dormancy + 10-min dreaming window into 7s, so a 90s run simulates ~12 hours of production wall-clock.
