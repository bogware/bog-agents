# Phase 17 — 2026-05-13 (per-prompt routing — mechanism + ambiguous validation)

Seventeenth real-world pass. Phase 14 found that `legacy-deletion`
at 55% treatment-win was an outlier among "technical" scenarios —
the prompt looks technical but reads as a decision/judgment
question. Phase 17 builds **per-prompt routing**: classify the
user's prompt at each call, and override the injection wrapper
when the prompt is decision-shaped.

## TL;DR

* **Mechanism ships clean.** New `classify_prompt_domain()` +
  `_has_decision_signal()` + 7 unit tests. The middleware now
  optionally routes per-call.
* **Validation experiment (N=45 across 3 scenarios) is ambiguous-
  to-negative.** Per-prompt routing fires correctly but does not
  reliably improve outcomes when the host agent is engineering-
  classified.
* **Shipping decision: knob defaults OFF.** `use_prompt_routing=False`.
  The Phase 11/12 agent-level routing is the load-bearing decision;
  per-prompt is a refinement that didn't pay off at this N.

## The mechanism

```python
# domain.py
def classify_prompt_domain(prompt: str) -> Domain:
    """Reuse the agent-profile classifier vocabulary, then apply a
    decision-signal override: 'should I', 'which approach',
    'trade-off' → creative routing even when surface vocabulary
    is technical."""
    base = classify_agent_domain(prompt)
    if _has_decision_signal(prompt) and base in ("engineering", "general"):
        return "creative"
    return base
```

The decision-pattern list (18 patterns) was hand-tuned against the
Phase 10/14 scenario set:

```
"should i", "would you call", "would you recommend", "what would you",
"what's the right way", "right way to", "decide between", "decision",
"which approach", "which one", "is it better", "is it worth",
"trade-off", "tradeoff", "trade off", "which lens", "name for",
"what would you call"
```

In `imagination.py`, the middleware grows `_route_style_for_request()`
which extracts the user's last `HumanMessage` and classifies it.
If `use_prompt_routing=True` in config, the classification overrides
the configured `injection_style` for that one call only.

7 new unit tests cover: classifier behavior on pure-technical /
decision-shaped-technical / pure-creative / empty prompts; the
decision-signal helper's pattern matches; and middleware-level
integration with both routing on and off.

## The validation experiment

The mechanism works; does it help? I picked 3 Phase 14 scenarios
and re-ran them with `use_prompt_routing=True` at N=15 each.

| Scenario | Phase 16 (EC + neutral) | Phase 17 (routed → dreams) | Direction |
|---|---|---|---|
| **legacy-deletion** | 87% [62%, 96%] | **67%** [42%, 85%] | worse |
| **refactor-decision** | 60% [36%, 80%] | **60%** [36%, 80%] | same |
| **retry-under-load** | 60% [36%, 80%] | **33%** [15%, 58%] | worse |

The middleware correctly identified all three as decision-shaped
(all 45 trials got the dreams wrapper) — including `retry-under-
load`, which I'd expected to keep the neutral wrapper. The
classifier triggered creative on it because the prompt opens with
*"I'm designing the retry policy"* and `"designing"` is in the
creative vocabulary. Debatable but not unreasonable.

But the *effectiveness* moved the wrong direction on two of three.
Both Phase 17 CIs overlap Phase 16's — at N=15 we can't formally
claim a real regression — but the point estimates argue against
the hypothesis that per-prompt routing helps engineering agents.

## Why the hypothesis didn't pan out

Best guess: **the agent's voice matters more than the wrapper at
the call level.** An engineering-profiled agent's response style is
engineering. Forcing a *"You appear to be stuck. Here is some
imagination."* framing for a decision-shaped prompt doesn't
recreate the Phase 11 creative-prompt magic, because the Phase 11
magic came from **creative agents** getting dreams wrapper — both
halves aligned with creative work.

When an engineering agent gets dreams wrapper for a decision
prompt, you get an engineer trying to use the language of
imagination on a problem they'd rather solve with tool names. The
result is *neither* the crisp directness of the neutral wrapper
*nor* the evocative reframe of the creative-agent + dreams
combination.

## Shipping decision

* **Phase 17 mechanism ships.** Code + tests landed. The knob
  exists.
* **Defaults preserved.** `use_prompt_routing=False`. agent.py
  does NOT auto-enable it. Engineering agents continue using
  neutral wrapper for all prompts (Phase 16's 57% win rate is
  the validated baseline).
* **Phase 11/12 agent-level routing stays the load-bearing
  decision.** Creative agents → dreams wrapper; engineering →
  neutral wrapper; both validated at N=140 in Phase 14.
* **Power-users can opt in** to per-prompt routing by setting
  `use_prompt_routing=True`. The mechanism is preserved for future
  research and for users who want to A/B test on their own
  workloads.

## What this means for the campaign

Phases 13-17 built a sequence of refinements: routing layer
verified (P13), domain-conditional effect proven at N=140 (P14),
engineering-craft seeds validated (P15), seed library doubled
(P18), engineering-craft + neutral wrapper makes treatment
break-even-to-positive on technical work (P16), per-prompt routing
mechanism shipped but not auto-enabled (P17).

**The shipping defaults are now:**
* Creative agents: dreams wrapper, varied seeds
* Engineering agents: neutral wrapper, engineering-craft-first seeds
* Research/general agents: neutral wrapper, balanced seeds
* Per-prompt routing: shipped, default off

Phase 17's ambiguous result is itself informative — it tells us
the agent-level routing is *enough*, and finer-grained per-call
routing doesn't (at this N) provide further lift. That's a
"this dial doesn't need to be turned" finding.

## Verdict

**MIXED — mechanism solid, default keeps it off.** The honest
phase: ship the knob with sensible defaults; document the
validation finding; move on. Future research can run larger trials
to confirm or refute the directional negative result.

## Next steps

  agent build (cached) would handle the long tail.
* **Phase 20 — N=30 per-scenario re-run.** Confirm or refute the
  Phase 17 directional finding with proper statistical power.
* **Phase 21 — content-level per-prompt routing** instead of
  wrapper-level. Pick the seed *archive* per prompt (engineering-
  craft for engineering-shaped, broader mix for decision-shaped)
