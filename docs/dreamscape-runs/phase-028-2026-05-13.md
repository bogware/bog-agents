# Phase 28 — 2026-05-13 (telemetry exporter)

Twenty-eighth real-world pass. Phase 25 shipped the production
telemetry infrastructure — events accumulate in per-agent JSONL
logs. Phase 28 closes the loop: a bundler that packs telemetry
from one or more agents into a single portable JSON file, with a
privacy mode for cross-org aggregation.

## TL;DR

**Pure infrastructure, no LLM cost.**

* `bog_agents_cli/dreamscape/telemetry.py` gains
  `list_agents_with_telemetry()` and `export_telemetry_bundle()`
* `/dreamscape export [path] [--no-metadata]` slash subcommand
* **5 new unit tests** cover discovery, bundle shape, privacy mode,
  since-filter, auto-discovery.

## What `/dreamscape export` does

```
$ /dreamscape export
Telemetry exported
  Path: ~/.bog-agents/telemetry-export-20260513-181500.json
  Agents: 3
  Events: 47 (12 dreams, 18 injections)
  Metadata included: yes
```

The bundle is a single JSON file with this shape:

```json
{
  "schema_version": 1,
  "generated_at": 1778720000.0,
  "since": null,
  "include_metadata": true,
  "agents": {
    "myagent": {
      "events": [
        {"ts": ..., "kind": "dream_fired", "agent_id": "myagent",
         "metadata": {"title": "...", "category": "engineering-craft"}},
        ...
      ],
      "summary": {
        "events_total": 23,
        "dreams_fired": 8,
        "injections_fired": 12,
        "injections_helped": 9,
        "helped_rate": 0.75,
        "approx_cost_usd": 0.008,
        "dreams_by_category": {"engineering-craft": 6, "myth": 2},
        "injections_by_style": {"neutral": 10, "dreams": 2}
      }
    }
  },
  "summary": {
    "agent_count": 3,
    "total_events": 47,
    "total_dreams": 12,
    "total_injections": 18,
    "total_injections_helped": 14
  }
}
```

## Privacy mode

`/dreamscape export --no-metadata` strips event-level metadata:

```json
{
  "events": [
    {"ts": 1778720000.0, "kind": "dream_fired", "agent_id": "myagent"},
    {"ts": 1778720060.5, "kind": "injection_fired", "agent_id": "myagent"}
  ]
}
```

Dream titles, injection styles, and content categories are
omitted at the event level. The per-agent summary still reports
the *counts* (it sums by category/style during aggregation, not
from the stripped events) — useful for cross-org aggregation
where individual prompt-derived content shouldn't leak but
deployment-level patterns are fine to share.

## What this unlocks

* **Cross-deployment aggregation.** An operator running dreamscape
  across multiple projects can `/dreamscape export` and see
  unified counts.
* **Future Phase 29 analysis.** Once real telemetry accumulates,
  compare against the offline judge proxies from Phases 10-26.
  Disagreement is informative.
* **Privacy-respecting research.** Researchers studying dreamscape
  in their organizations can ship the privacy-mode bundle to a
  central team without prompt-content disclosure.
* **Cost auditing.** Operators can answer "what did dreamscape
  cost me this month across all my agents?" with one command.

## Tests

5 new unit tests under `TestTelemetryExporter`:

1. `list_agents_with_telemetry` returns only logged agents
   (ignores profile-only directories).
2. Export bundle includes all agents + sums correctly.
3. Privacy mode strips metadata (no prompt-derived content leaks).
4. Since filter respects timestamp lower bound.
5. `agent_ids=None` auto-discovers via the agents dir.

All 5 pass against the freshly-built infrastructure.

## What we deliberately didn't ship

* **No remote-export adapter** (S3, HTTPS POST, etc.). The bundle
  is a local file the operator moves manually. Easy to add later;
  intentionally not shipped without a security review.
* **No "maximum privacy" mode** that also blanks the per-agent
  summary categories/styles. Phase 33 (suggested).
* **No JSONL streaming** for >10MB logs. Acceptable at current
  scales; can be added when needed.
* **No live demo** — Phase 25 already exercised the upstream
  telemetry pipeline end-to-end. Phase 28 is just the bundler,
  covered by 5 unit tests against synthetic events. A real live
  demo would require accumulating events from real usage, which
  is exactly what the exporter enables.
